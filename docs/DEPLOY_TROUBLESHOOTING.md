# 🔧 Deploy Troubleshooting Guide

## Railway Build Failures

### Error: "railpack failed to prepare the build"

**Causa:** Dependências não instaladas ou falta de lockfile

**Solução:**
```bash
# No seu PC local:
cd /home/user/gestaomfx

# Instale dependências do workspace
npm install

# Isso vai criar lockfiles em cada app
# Railway vai detectar e usar automaticamente
```

### Error: "Cannot find module '@prisma/client'"

**Causa:** Prisma não foi gerado durante build

**Solução:** ✅ Já corrigido no `package.json`
- Adicionado `postinstall` script
- Build agora roda `prisma generate` automaticamente

### Error: "Error: ENOENT: no such file or directory, open '.env'"

**Causa:** Variáveis de ambiente não configuradas no Railway

**Solução:**
1. No painel Railway, ir em "Variables"
2. Adicionar todas as variáveis de `.env.example`
3. Re-deploy

### Build Takes Too Long / Timeout

**Solução:**
```bash
# Railway pode precisar de mais tempo
# Vá em: Deploy → Build Configuration
# Aumentar timeout para 30min
```

## Vercel Deploy Failures

### Error: "Build failed with exit code 1"

**Causa:** Framework não detectado ou config incorreta

**Solução:** ✅ Já corrigido
- Criado `vercel.json` com config específica
- Adicionado `.vercelignore` para ignorar backend

### Error: "Cannot find page"

**Causa:** Next.js App Router não configurado

**Solução:** ✅ Já corrigido
- Estrutura `apps/frontend/src/app/` criada
- `layout.tsx` e `page.tsx` presentes

### Environment Variables Not Available

**Solução:**
1. No painel Vercel, ir em "Settings → Environment Variables"
2. Adicionar:
   ```
   NEXT_PUBLIC_API_URL=https://seu-backend-railway.railway.app/api
   NEXT_PUBLIC_APP_URL=https://seu-frontend.vercel.app
   ```
3. Re-deploy

## Local Development

Se você quiser testar localmente antes de fazer deploy:

```bash
# Install all dependencies
npm install

# Start services
docker-compose up -d

# Terminal 1: Backend
cd apps/backend
npm run dev

# Terminal 2: Frontend
cd apps/frontend
npm run dev

# Access:
# - Backend: http://localhost:3002
# - Frontend: http://localhost:3000
```

## Railway Specific Steps

### 1. Connect Repository
```
1. Go to https://railway.app/dashboard
2. Click "New Project"
3. Select "Deploy from GitHub"
4. Choose: maferreiraa/gestaomfx
5. Select branch: claude/photo-selection-download-system-pjp9nd
```

### 2. Configure Environment
```
1. In Railway dashboard, click on your project
2. Go to "Variables"
3. Add from `.env.example`:
   - DATABASE_URL (auto-generated by PostgreSQL plugin)
   - JWT_SECRET
   - AWS_ACCESS_KEY_ID
   - AWS_SECRET_ACCESS_KEY
   - AWS_S3_BUCKET
   - MERCADO_PAGO_ACCESS_TOKEN
   - FRONTEND_URL
   - NODE_ENV=production
4. Click "Save"
```

### 3. Deploy
```
1. Railway should auto-detect the changes
2. Check "Deployments" tab
3. Watch the build logs
4. Once green ✅, note your Railway domain
```

## Vercel Specific Steps

### 1. Connect Repository
```
1. Go to https://vercel.com/new
2. Click "Import Git Repository"
3. Paste: https://github.com/maferreiraa/gestaomfx
4. Authorize Vercel
```

### 2. Configure Project
```
1. Project Name: gestaomfx-frontend
2. Framework Preset: Next.js
3. Root Directory: apps/frontend ← IMPORTANT!
4. Environment Variables:
   - NEXT_PUBLIC_API_URL=https://your-railway-backend.railway.app/api
   - NEXT_PUBLIC_APP_URL=https://your-vercel-frontend.vercel.app
```

### 3. Deploy
```
1. Click "Deploy"
2. Wait for build to complete
3. Copy your Vercel URL
4. Update Railway FRONTEND_URL variable
5. Trigger rebuild in Railway
```

## Still Having Issues?

1. **Check the actual error message** - Railway and Vercel provide detailed logs
2. **Verify all env vars** are set correctly
3. **Ensure Node version** is 20+ (`.nvmrc` file controls this)
4. **Check database URL format** - PostgreSQL expects specific format
5. **Verify GitHub repo** is public or Vercel/Railway have access
